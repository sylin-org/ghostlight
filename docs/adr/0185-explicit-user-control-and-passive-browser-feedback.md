# ADR-0185: Explicit User Control and Passive Browser Feedback

Date: 2026-09-28. Status: Accepted by owner direction.

Supersedes ADR-0079's denial circuit and interactive page overlay, and ADR-0157's automatic
session attention and review/resume journey. Preserves their final dispatch checks, explicit
human Pause/Stop controls, and truthful effect reporting. Amends ADR-0133's unconditional
credential handoff and the current 1.0 contracts.

## Context

The owner rejected pausing an agent after repeated policy denials as extra busywork. Ghostlight
enforces configured authority for each request; it does not regulate the agent's behavior.
The owner also rejected buttons over the user's browser page. Messages and animations are
permitted, but interactive runtime control belongs in the Tauri workbench.

A credential field needs a clear response to the caller, not a persistent session hold.
When the user explicitly instructs the agent to enter credentials, Ghostlight must permit
that request subject to the same configured authority and explicit human controls.

## Decision

1. Remove denial counters and automatic session attention. Any number of refused requests leaves
   later permitted work available. Each refused request keeps its ordinary outcome and audit.
2. Remove the injected attention dialog and its buttons. In-page feedback is passive, bounded,
   and cannot intercept pointer or keyboard input, including when its stylesheet is unavailable.
   Legacy explicit attention signals may produce a passive message only.
3. Credential detection returns guidance for the current fill or typing request when explicit
   authorization is absent. It creates no session state, incident, resume requirement, or UI
   approval round trip. No input from that request is dispatched before grouped preflight passes.
4. Fill and typing inputs accept `user_authorized_credentials`, false by default. The caller sets
   it only when the user explicitly authorized credential entry. Existing authorization in the
   conversation is sufficient; the user need not repeat it. The acknowledgement applies only to
   that request and may be supplied on the first call. It is not a grant or independently verified
   proof of user intent. Configured policy and explicit Pause/Stop remain authoritative.
5. The orchestrator conveys the acknowledged physical input through a closed browser-command
   field. Browser preflight and immediate input checks honor the same value. Values never enter
   audit, diagnostic logs, or presentation. Credential metadata remains available for observation
   and privacy-safe feedback.
6. File upload already requires explicit files or a captured image and a physical file input.
   Credential-like names on a file control do not create a credential-entry handoff.
7. Explicit global runtime attention remains compatible with the existing local control surface.
   It is not generated by policy refusals or credential input. Human controls retain the final
   dispatch boundary and never imply rollback of already dispatched work.

## Verification

Prove that repeated refusals do not prevent a later permitted request; unacknowledged credential
input returns guidance without holding subsequent work; explicitly acknowledged input reaches
the browser while policy and human holds still apply; and the page renderer creates no buttons,
focusable controls, or input-intercepting layer. Verify authorized password input through the
real browser mechanism, including grouped fill and focused typing, without retaining values.
