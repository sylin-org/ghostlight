# R8: Full integration and behavioral parity proof

## Goal

Prove the restored capability families through the real executable graph and a live reloaded Chrome
extension, then reconcile every behavioral claim.

## Required work

- Add one checked current behavioral matrix that maps every published 0.8 browser job to a current
  test, an explicit supersession, or a separately owned deferral. It must fail when a row loses its
  evidence.
- Run the full common gate from `BOOTSTRAP.md` against fresh isolated binaries.
- Extend the process journey through MCP connector, orchestrator, browser connector, and adapter
  fixture for every R1-R7 capability family.
- Reload the exact unpacked extension built from the current tree and run live Chrome journeys for
  REPL, precision input, semantic form/action loops, article/tree/diff reads, inline and captured
  image upload, result-aware flow, and guarded navigation.
- Exercise failure paths: ambiguity, credentials, stale handles, old capability revision, bounds,
  cancellation, post-dispatch uncertainty, and denied landing.
- Reconcile `docs/1.0/` contracts, `docs/0.8/` recovery claims, `docs/STATUS.md`, and public trust
  claims only to the evidence now present.

## Evidence

- Exact commands, test totals, binary hashes, extension source hash, browser version, and journey
  results recorded in the ledger or a linked dated testing document.
- The live catalog contains exactly the documented 23 tools and no historical aliases.
- A second fresh MCP client sees the same catalog and complete ordinary-text results.

## STOP conditions

- Any family has only a unit test or fixture simulation but no real process-boundary proof.
- Live Chrome is not running the exact current extension bytes.
- A current public or trust claim cannot be supported without softening it.
