# S7: reference evaluation

## Objective

Demonstrate that the combined experience is understandable, calm, reliable, and recoverable for
real Linux users. Automated correctness is necessary but not sufficient.

## Prompt outline

1. Build a small evaluation cohort that covers, at minimum, a mainstream GNOME newcomer, a KDE or
   keyboard-first power user, a privacy-sensitive user who disables automatic launch or page
   presence, and a user with multiple browsers, profiles, or harnesses. Record consented,
   content-free observations.
2. Give participants outcomes, not product instructions. Include first use without opening the
   workbench, navigation while the browser is closed, manual-start behavior, missing adapter
   diagnosis, opening At a glance from the browser, pause, resume, stop, and recovery after a
   connector or browser interruption.
3. Add adversarial automated journeys for simultaneous requests, ambiguous browsers, unsupported
   packages, stale owned registration, caller timeout, partial or uncertain effects, plural
   sessions, workbench closure, restart, and clean removal.
4. Measure whether users can identify readiness, controller, current activity, paused state, and
   the next repair action without logs or terminal help. Measure interruptions and repeated
   prompts, not only task completion time.
5. Test keyboard-only use, screen reader names, large text, high contrast, reduced motion, browser
   zoom, fractional desktop scaling, GNOME Wayland, and KDE Wayland.
6. Fix findings at their owning seam. Do not paper over a domain ambiguity with more explanatory
   copy. Rerun the affected scenario and record before/after evidence.
7. Close with an explicit disposition for every acceptance measure from S1 and every deviation in
   the ledger.

## Completion evidence

- Dated, consented, content-free user evaluation records covering the required cohorts.
- Automated adversarial journeys for every closed recovery and control state.
- Live GNOME and KDE evidence for the browser affordance, workbench, activation, and controls.
- No unresolved critical finding in first use, pause/stop truth, automatic recovery, accessibility,
  or ownership-safe removal.
- A final ledger row links every S1 measure to evidence or an explicit owner-accepted deferral.
- Active documentation describes only the experience that the evidence proved.

## Stop conditions

- Completion is being inferred from automated tests alone.
- Evaluation requires participants to understand MCP, native messaging, or process topology.
- A finding is being fixed in presentation when its cause belongs to lifecycle, execution,
  governance, or completion.
- Sensitive browser content would enter a tracked artifact.
