# Ghostlight 0.8 artifact recovery

The test recovery matrix covers behavior. This ledger covers files. Together they prevent a clean
implementation boundary from becoming another knowledge wipe.

`artifact-inventory.json` records every path and Git blob in the mature 0.8 revision
`c01cc3276102471f3e18de2ae90cb90abf98ed88`, plus its relationship to the current working tree.
`artifact-recovery.json` gives every one of those paths an explicit treatment. Both files are
generated by `scripts/harvest-0.8-artifacts.ps1` and checked for drift by
`scripts/check-0.8-artifacts.ps1`.

## Meaning of a treatment

- `retained-identical`: the current tree contains the exact old blob at the same path.
- `retained-evolved`: the path remains active and current contracts govern its new contents.
- `behavior-dispositioned`: the old test or Lightbox implementation is covered by the separate
  checked behavior recovery matrix.
- `historical-implementation-only`: keep the code in Git history and translate observable
  behavior onto current seams. Never copy old internals into the clean-room implementation.
- `restore-lean`: the old artifact carries a current, high-value operational lesson and should
  return as an independent small command or policy file.
- `redesign-after-signed-candidate`: the old raw-binary distribution shape is real history, but it
  cannot describe the 1.0 native desktop package before signed artifacts exist.
- `retired-low-value-conductor`: preserve the release safeguards, not the large cross-channel
  orchestration script.
- Other treatments name the current workflow or historical boundary that owns the artifact.

## High-value absences

The ledger deliberately calls out the static Windows runtime policy, one-command dev replacement,
Chrome OAuth recovery, and independent extension publication for lean restoration. It keeps npm,
MCPB, Homebrew, Scoop, WinGet, and one-line installers visible but deferred until they can target
the actual signed 1.0 release unit. That is a sequencing dependency, not permission to forget
them.

The generated JSON is the exhaustive source of truth. This document explains the policy and does
not duplicate hundreds of path rows by hand.
